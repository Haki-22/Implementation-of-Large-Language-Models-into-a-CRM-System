# `substrate/pipeline/data_acquisition/` — the public inputs

Everything the substrate is built from that is *not* generated here comes from
three public sources: Amazon/SNAP, the Czech Statistical Office (ČSÚ), and
Czech Post. This package downloads and checks those inputs.

| file / dir | what |
| --- | --- |
| `downloaded/` | **every pinned download lands here**, nowhere else: the two Amazon Electronics dumps (SNAP, 2014) and `downloaded/csu/` with the ČSÚ population tables + the Czech Post postal-code list. Not tracked in git; `build_all --force` fetches what is missing and verifies size + md5 before any build step reads them. |
| `inputs.py` | one status + ensure function over all of the above (`raw_status`, `ensure_raw_inputs`); `build_all --force` fetches what is missing through it, and the demo frontend can ask the same question |
| `_pinned.py` | the shared verify / download mechanism: pins (url, size, md5), `.part` transfer, loud failure on drift |
| `fetch_and_filter.py` | Amazon: pins + `--download` / `--verify-only`, and the stratification of the 425 reviewers inside the frozen-translation pool → `stratified_500_users.json` |
| `fetch_csu.py` | ČSÚ + Czech Post: pins + `--download` / `--verify-only`, and the reduction to `data/cz_age_sex.csv` and `cz_municipalities.csv` (provenance headers) |
| `stratified_500_users.json` | derived, not downloaded: the 425 stratified reviewers with their reviews and products (247 MB; not tracked, regenerated by the `amazon` step) |

## How to use

Run from the repository root with the project environment active. Raw downloads are optional for database-only assembly from shipped snapshots. The full rebuild downloads missing raw inputs and replaces its generated outputs; verification does neither.

```bash
python -m substrate.pipeline.build_all --force          # fetches whatever is missing, then builds
python -m substrate.pipeline.data_acquisition.fetch_and_filter --verify-only
python -m substrate.pipeline.data_acquisition.fetch_csu --verify-only
```

The derived tables this package writes live next to their readers
(`data/`), not here: `downloaded/` holds downloads only.
